# Gym Tracker

https://alexander-768.github.io/gym_tracker/

## Хранение

Единственный рабочий журнал — `gym_tracker_app`. Старые вкладки остаются архивом. Приложение сохраняет запись локально в IndexedDB, затем синхронизирует её с Google Sheets. Удаление мягкое: сохраняется `deleted_at`. Редактирование сохраняет ID и обновляет `updated_at`.

Столбцы: id,date,exercise,weight_kg,reps,sets,note,created_at,updated_at,deleted_at,category. Исторические ID legacy: сохраняются без изменений. Разовая миграция и прежний импорт JSON удалены из приложения в v20. Ручной экспорт JSON доступен, не изменяет базу.

## Автоматические резервные копии (отдельная настройка)

1. Открой https://script.google.com/ и создай новый отдельный проект Apps Script.
2. Скопируй содержимое файла [backup.gs](backup.gs) в редактор.
3. Сохрани проект, выбери функцию installGymBackup, запусти и разреши доступ к своим Google Sheets и Drive.
4. Убедись, что в Google Drive создана папка Gym Tracker Backups с первым JSON-файлом. Проверь раздел Triggers: backupGymDaily, раз в сутки около 03:00 Europe/Helsinki.
5. Скрипт сохраняет только журнал, включая удалённые строки. Срок хранения в папке — 15 календарных дней. После успешной проверки новой копии старые файлы, созданные этим скриптом, переносятся в корзину. Корзина Google Drive учитывается в квоте до окончательного удаления. Скрипт не очищает чужие файлы и не меняет исходную таблицу. Если журнал пуст, заголовки неожиданно изменились или найдены дубли ID, скрипт прекращает работу без очистки.

Восстановление: сначала сохранить текущую таблицу, затем открыть резервный JSON, проверить headers и rows и восстановить нужные строки в отдельной тестовой таблице. Не заменять рабочий лист без проверки синхронизации устройств. Автоматического восстановления нет.

Резервные копии не включают изменения, ещё не отправленные из браузера. Для независимой защиты от потери доступа к Google хранить периодическую копию локально. Данные пользователя в GitHub не публикуются.
